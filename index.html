Partie 1

Contexte et problème

Problème du Data Lake classique

  • Gestion des fichiers Parquet peu structurée
  • DELETE / UPDATE complexes
  • Historique des versions difficile
  • Schema change coûteux et risqué
  • Récupération après erreur limitée

Conséquences

  • Moins de fiabilité analytique
  • Peu de reproductibilité
  • Contrôle des données faible
  • Défis pour la gouvernance
Note : Les data lakes modernes offrent flexibilité, mais manquent souvent de gestion structurée des tables et des versions.

Partie 2

Pourquoi Apache Iceberg ?

Apache Iceberg est un format de table open source conçu pour gérer des données stockées dans un système de fichiers objet comme S3, GCS ou MinIO.

Sans Iceberg

  • Fichiers parquet dispersés
  • Pas de versioning table
  • Mise à jour coûteuse

Avec Iceberg

  • Métadonnées centralisées
  • Snapshots transactionnels
  • Time Travel et rollback

INSERT de nouvelles lignes
T2
UPDATE / DELETE logique

Nouveau snapshot déclaré
Une table Iceberg ne change pas par écriture “en place” ; elle produit de nouveaux snapshots explicites.
Partie 2

Time Travel

Le système permet de consulter une version précédemment validée sans modifier l’état actuel de la table.

SELECT * FROM local.sales
VERSION AS OF 1234567890123;
Utile pour l’audit, le debug, l’analyse historique et la comparaison des résultats entre versions.
Partie 2

Rollback

Erreur détectée

Suppression ou UPDATE incorrect.

Action

Retour au snapshot antérieur et restauration du bon état.

CALL local.system.rollback_to_snapshot('table_name', 'snapshot_id');

Partie 3

Exemple de configuration Spark + Iceberg

spark = (
  SparkSession.builder
    .config("spark.sql.extensions", "org.apache.iceberg.spark.extensions.IcebergSparkSessionExtensions")
    .config("spark.sql.catalog.local", "org.apache.iceberg.spark.SparkCatalog")
    .config("spark.sql.catalog.local.type", "hadoop")
    .config("spark.sql.catalog.local.warehouse", "s3a://warehouse")
    .config("spark.hadoop.fs.s3a.endpoint", "http://minio:9000")
    .getOrCreate()
)
Cette configuration montre la séparation claire entre moteur d’exécution (Spark), table format (Iceberg) et stockage objet (MinIO).

Ce que le projet a démontré

  • L’intérêt d’un stockage objet avec une couche de métadonnées

Partie 4

Conclusion

Apache Iceberg apporte la gestion structurée des tables à un stockage de type data lake, ce qui en fait un élément clé pour les architectures Lakehouse modernes.

Le projet valide que les données peuvent rester flexibles dans le lake tout en bénéficiant des avantages du warehouse : fiabilité, historique, audit et récupération.
